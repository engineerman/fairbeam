# EMerge pin 3.0.0b12 Implementation Plan

> **For agentic workers:** Use `.cursor/skills/emerge-agent-workflow`. Implement task-by-task with checkbox tracking. Planner = capable model; implementer = mid (lock + API).

**Goal:** Move the managed / supported EMerge pin from `2.8.9` to `3.0.0b12` so Fairbeam planar/fixture runs use the faster 3.0 solver the hairpin bakeoff already measured.

**Architecture:** Same Elmer-style optional managed venv (`emerge_runtime` + hash lock). Only the pinned wheel set, version allow-list, docs/i18n strings, and any worker API deltas change. openEMS stays default; EMerge stays opt-in experimental.

**Tech Stack:** Fairbeam Python + SolidJS; `uv pip compile` hash lock; unittest; Windows cp313 wheels.

## Global Constraints

- openEMS remains the default solver.
- EMerge is opt-in experimental only; no stock-installer bundle.
- Human (2026-11-04): authorize **beta** pin `3.0.0b12` for speed (RFSim hairpin ~7 min on 3.0 vs ~17 min on 2.8.9).
- Recheck license on the new wheel before committing the pin (SCOPE.md). Prefer GPL-2.0-or-later reading if upstream still offers it.
- Unsupported geometry is rejected, never silently dropped.
- UI strings: `en.json` + `tr.json`. Pass `npm run check:legal`.
- Docs numbers require reproducible runs (wall clock after reinstall).
- Branch: `feat/emerge-experimental`. Follow `AI_POLICY.md` trailers.
- Keep worker `run_sweep(parallel=False, multi_processing=False)` unless a separate plan opens parallelism.
